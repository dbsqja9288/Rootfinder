## 2. 무엇이 문제였나

데이터에는 **정답이 이미 들어 있었습니다.**

| 본관 | 데이터의 한자 | 실제 지역 | 화면에 나온 것 |
| --- | --- | --- | --- |
| 광주 이씨 | 廣州 | 경기도 광주시 | ❌ 광주광역시 |
| 광주 안씨 | 廣州 | 경기도 광주시 | ❌ 광주광역시 |
| 광주 노씨 | 光州 | 광주광역시 | ✅ 광주광역시 |

지역 사전이 **한글 이름만 열쇠로 쓰고 있어서**, 廣州든 光州든 &lsquo;광주&rsquo; 하나로 조회됐습니다.
셋 중 둘이 틀린 상태였습니다.

### 고친 방법

한자를 먼저 보고, 한자가 없을 때만 한글로 찾도록 바꿨습니다.

```
getRegion("광주", "廣州") → 경기도 광주시
getRegion("광주", "光州") → 광주광역시
```

### 같은 유형을 전수 검사했더니

제보 하나를 고치고 끝내면 나머지는 그대로 남습니다. 그래서 **한글이 같은데 한자가 다른 본관을
전부 찾아냈고**, 세 건이 더 나왔습니다.

- 영양 남씨(英陽, 경북 영양) / 영양 천씨(潁陽, 중국 허난성) — 둘 다 경북 영양으로 표시되던 것 수정
- 서산 진씨(眞) — 본관 한자가 `西山` 으로 잘못 들어가 있어 `瑞山` 으로 수정
- 서산 진씨의 시조 — 확인되지 않은 이름이 적혀 있어 &lsquo;미상&rsquo;으로 정정
  (서산 진씨는 시조와 계보가 전하지 않습니다)

## 3. 앞으로 CS를 줄이는 장치 (다 넣었습니다)

### ① 자동 점검기 — 같은 실수의 재발 방지

```
npm run check:regions
```

한글이 겹치는데 한자로 갈라두지 않은 본관이 있으면 **빌드가 실패**합니다.
새 성씨를 추가하다 실수해도 사람이 아니라 기계가 먼저 잡습니다.

### ② 한자 병기 — 애초에 오해가 안 생기게

본관 지역 옆에 `(廣州)` 처럼 한자를 함께 띄웠습니다.
&ldquo;내가 아는 광주가 저 광주가 맞나?&rdquo; 를 이용자가 스스로 확인할 수 있습니다.

### ③ 구조화된 제보 버튼 — 왕복을 없앰

각 본관 페이지 아래 **&lsquo;잘못된 정보 알려주기&rsquo;** 버튼을 넣었습니다.
누르면 이런 메일이 **미리 채워져서** 열립니다.

```
제목: [정보 정정] 광주 이씨

─── 현재 사이트에 표시된 내용 ───
페이지: https://.../surnames/lee/광주
본관 한자: 廣州
시조: 이자성(李自成)
본관 지역: 경기도 광주시
────────────────────────

■ 어느 항목이 잘못되었나요?
■ 올바른 내용은 무엇인가요?
■ 근거가 되는 자료가 있다면 (선택)
```

**이게 CS 공수를 가장 크게 줄입니다.** 지금까지는 &ldquo;어느 페이지인가요?&rdquo;, &ldquo;한자가 뭐로 나오나요?&rdquo;를
되묻느라 메일을 두세 번 주고받아야 했는데, 이제 첫 메일에 판단에 필요한 게 다 들어옵니다.

### ④ 정정 내역 공개 — 중복 제보 차단

`/corrections` 페이지를 만들었습니다. 푸터에서 바로 갈 수 있습니다.

같은 걸 제보하려던 사람이 &ldquo;이미 고쳤구나&rdquo; 하고 돌아갑니다. 제보한 분은 반영됐는지 직접
확인할 수 있고, 자료를 성의 있게 관리한다는 신호도 됩니다.
덤으로 **애드센스가 좋아하는 &lsquo;직접 쓴 고유 콘텐츠&rsquo;** 이기도 합니다.

## 4. 메일 자동 분류 (원하시면 다음 단계)

지금까지는 **들어오는 CS를 줄이고 처리를 쉽게** 만든 것입니다.
메일 자체를 자동으로 읽고 분류하려면 **Gmail 연결**이 필요합니다.

claude.ai → 설정 → 커넥터에서 **Gmail** 을 연결하시면, 그 다음은 제가 세팅합니다.

연결 후 가능한 것:

- 매일 정해진 시각에 새 메일을 읽어 **정정 요청 / 문의 / 스팸**으로 분류
- 정정 요청은 사이트 데이터와 **자동으로 대조**해서 진짜 오류인지 1차 판단
- **답장 초안을 Gmail 임시보관함에 저장** — BJ님은 읽고 보내기만
- 하루치 요약 보고

> ⚠️ 다만 **메일 내용대로 데이터를 자동으로 고치는 것은 권하지 않습니다.**
> 족보는 문중마다 주장이 갈리는 영역이라 검증 없이 반영하면 오히려 부정확해지고,
> 악의적인 제보로 내용이 훼손될 수도 있습니다.
> 자동화는 **분류와 초안 작성까지**, 최종 반영은 사람이 판단하는 선이 안전합니다.

## 5. 제보가 왔을 때 판단 기준

대부분의 제보는 다음 셋 중 하나입니다.

| 유형 | 어떻게 | 예 |
| --- | --- | --- |
| **명백한 오류** | 바로 고치고 `/corrections` 에 기록 | 이번 광주 이씨 건 |
| **문중마다 갈리는 사안** | 양쪽 설을 병기하고 &lsquo;∼로 전한다&rsquo; 로 표기 | 시조의 도래 시기, 분파 시점 |
| **자료가 없는 사안** | 없다고 그대로 적기 | 서산 진씨의 시조 |

세 번째가 중요합니다. **모르는 것을 채워 넣으면 반드시 CS가 됩니다.**
비워두거나 &ldquo;전하지 않는다&rdquo; 고 적는 편이 낫습니다.
