# 성과 분석 자동화 — 설정 안내

매일 자동으로 성과를 읽고 보고받기 위한 준비입니다. **한 번만 하면 끝**입니다.

---

## 1. MARKETING_KEY 정하기 (30초)

대시보드와 성과 요약 주소를 지키는 열쇠입니다. 이미 넣으셨다면 그대로 두고 값만 알려주세요.

Vercel → 프로젝트 → **Settings → Environment Variables**

| Key | Value |
| --- | --- |
| `MARKETING_KEY` | 아무 문자열 (예: `bburi-2026-x9k2`) |

추측하기 어려운 값으로 하세요. 이 값을 아는 사람은 성과 데이터를 볼 수 있습니다.

## 2. GA4 연동 (10분, 한 번만)

트래픽 숫자를 읽으려면 구글에 "이 사이트 통계를 읽어도 된다"고 허락해줘야 합니다.
사람 계정 대신 **서비스 계정**(프로그램 전용 계정)을 하나 만들어 읽기 권한만 줍니다.

### 2-1. 서비스 계정 만들기

1. [console.cloud.google.com](https://console.cloud.google.com) 접속
2. 상단에서 프로젝트 새로 만들기 → 이름은 `rootfinder` 아무거나
3. 검색창에 **"Google Analytics Data API"** → **사용 설정**
4. 왼쪽 메뉴 **IAM 및 관리자 → 서비스 계정 → 서비스 계정 만들기**
   - 이름: `rootfinder-reader`
   - 역할은 **건너뛰기** (구글 클라우드 쪽 권한은 필요 없습니다)
5. 만들어진 계정 클릭 → **키** 탭 → **키 추가 → 새 키 만들기 → JSON** → 파일이 받아집니다

### 2-2. GA에 읽기 권한 주기

1. [analytics.google.com](https://analytics.google.com) → 왼쪽 아래 **관리(톱니바퀴)**
2. **속성 액세스 관리** → 오른쪽 위 **+** → **사용자 추가**
3. 이메일에 위에서 받은 JSON 파일 속 `client_email` 값을 붙여넣기
   (`rootfinder-reader@...gserviceaccount.com` 형태)
4. 역할은 **뷰어**로 지정 → 추가

### 2-3. 속성 ID 확인

같은 **관리** 화면 → **속성 설정** → 오른쪽 위 **속성 ID** (숫자 9자리)

### 2-4. Vercel에 넣기

받은 JSON 파일을 열어 두 값을 꺼냅니다.

| Key | 어디서 | 비고 |
| --- | --- | --- |
| `GA4_PROPERTY_ID` | 2-3에서 본 숫자 | 숫자만 |
| `GA4_CLIENT_EMAIL` | JSON의 `client_email` | |
| `GA4_PRIVATE_KEY` | JSON의 `private_key` | `-----BEGIN` 부터 `-----\n` 까지 **통째로** |

> `GA4_PRIVATE_KEY`는 길고 줄바꿈이 들어 있습니다. JSON에 적힌 그대로(`\n` 포함) 복사해
> 붙여 넣으면 됩니다. 코드가 알아서 줄바꿈을 되돌립니다.

**앞에 `NEXT_PUBLIC_`을 붙이면 안 됩니다.** 붙이면 브라우저로 새어 나갑니다.

## 확인하는 법

브라우저에서 아래 주소를 열어 JSON이 나오면 성공입니다.

```
https://rootfinder.kr/api/summary?key=(내가정한열쇠)
```

- `threads.ok: true` → 스레드 지표 읽힘
- `traffic.ok: true` → GA 트래픽 읽힘
- `automation.ok: true` → 자동 게시 실행 이력 읽힘

셋 중 하나가 `false`면 그 옆 `error`에 이유가 적혀 있습니다.

## 스레드 숫자는 어떻게 들어오나 (2026-08-26 추가)

**BJ가 할 일은 없습니다.** 한 번 읽어만 두세요.

### 왜 이렇게 만들었나

스레드 토큰은 깃허브 Secrets에 있는데, **Secrets는 한 번 넣으면 값을 다시 볼 수 없습니다.**
그래서 같은 토큰을 Vercel에 또 넣으려면 메타에서 새로 발급받아야 하고, 비밀 사본만 하나 더 늘어납니다.

방향을 뒤집었습니다. **토큰을 이미 가진 쪽(깃허브 액션)이 숫자를 받아서 저장소에 파일로 남깁니다.**

```
깃허브 액션 (토큰 있음)
   │  하루 한 번, 한국시간 08:30
   ├─→ 스레드에 물어봄
   └─→ data/threads-metrics.json 으로 커밋
              │
              ├─→ 사이트(/marketing)가 읽음  ← 토큰 필요 없음
              └─→ 내가 읽음                  ← 브라우저 안 빌려도 됨
```

토큰은 깃허브 한 군데에만 남고, 사람이 손댈 일이 없습니다.

### 관련 파일

| 파일 | 하는 일 |
| --- | --- |
| `.github/workflows/metrics.yml` | 하루 한 번(08:30 KST) 돌린다 |
| `scripts/collect-metrics.mjs` | 스레드에서 받아 파일로 쓴다 |
| `data/threads-metrics.json` | 결과물. 깃허브에서 그냥 열어봐도 읽힌다 |

### 지금 당장 최신으로 만들고 싶으면

깃허브 저장소 → **Actions** → 왼쪽 **스레드 성적 수집** → 오른쪽 **Run workflow**

### 알아둘 것

- **분류(어느 서비스·어느 문구)는 파일에 저장하지 않습니다.** 원본 글만 담고, 읽을 때마다 규칙을 다시 적용합니다. 그래야 규칙을 고쳤을 때 예전 글까지 새 규칙으로 다시 읽힙니다.
- 조회수는 며칠에 걸쳐 오릅니다. 같은 글을 다시 받으면 **새 숫자로 덮어쓰므로** 결국 최신값이 됩니다.
- 글은 최대 400개까지 쌓아두고 오래된 것부터 버립니다. 하루 18개씩이면 **약 3주치**입니다.
- 하루에 커밋이 하나 늘어납니다. Vercel이 그때 한 번 더 배포합니다.
- Vercel에 `THREADS_ACCESS_TOKEN`을 넣으면 그쪽이 우선합니다(실시간 조회). 안 넣어도 됩니다.
